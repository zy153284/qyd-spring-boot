# 回滚手册

## 触发条件

出现不可控超卖、资金不平、支付回调错误、核心接口持续不可用或迁移数据严重偏差时，由切换负责人
宣布回滚。不要在两个系统同时开放写入。

## 步骤

1. 立即停止新平台入口和后台写操作，记录时间、水位、镜像版本与数据库状态。
2. 暂停 Outbox 发布、库存超时任务和支付回调入口；保存未发布事件和回调请求。
3. 导出切换后新平台产生的订单、支付、退款、核销与结算增量，禁止直接丢弃。
4. 若旧系统从未恢复写入，按已审批的反向映射补录可兼容增量；无法安全反写时保持业务停机并人工处置。
5. 核对支付渠道流水后再恢复旧系统写入和流量；持续监控。
6. 新库保留只读证据，不执行破坏性降级；修复后重新完整演练。

数据库结构回滚不等于业务回滚。Flyway 已执行版本原则上使用前向修复脚本；只有经过备份恢复演练后
才允许恢复快照。支付成功但业务未落账、已核销和已退款记录必须逐笔闭环。
